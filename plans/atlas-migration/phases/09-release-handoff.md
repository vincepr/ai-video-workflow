# 09: Verify the combined migration and hand it off cleanly

## Read

All integrated phase handoffs and evidence; runbook delivery gates; repository README, ADRs 0001/0004/0007/0008/0012/0013/0016. Read handoff and skill-creator validation guidance for final instruction changes.

## Work

1. Run the combined offline acceptance matrix: direct no-presenter, presenter UGC, skit, drama and reference-remake routing; supported and unsupported provider cases; identical browser/agent requests; selected-context manifests and real fresh-session isolation.
2. Exercise interruption/recovery, ambiguous submission, cancellation, duplicate launch, cross-project paths, shared-key reservations and no paid calls from save/edit/navigation. Recheck that the default automatic path never needs redundant human confirmations.
3. Render and inspect representative final exports, including actual moving caption layers and encoded audio. Keep raw-generation defects and final creative judgments visible. Verify legacy still episodes, saved versions, inactive tabs, unchanged history and frozen media hashes.
4. Update concise workflow skills, usage commands and ADR status to match actual implementation. Document missing runtime/provider capabilities rather than marking them passed. Remove provisional interfaces only after all consumers use the final contract.
5. Run npm run check, npm run files and skill validation. Report Python tests separately until they are included in the repository check command. Check required tests rather than expanding into unrelated test work.
6. Commit only owned reusable changes; verify no media, local reviews, credentials, provider response dumps or product-specific configuration became tracked. Push completed changes to origin/main. Fetch origin and verify HEAD equals origin/main, a clean porcelain status and zero ahead/behind counts.
7. Create a small OS-temp handoff linking the implemented entry points, selected-context example, phase results, commands, known limitations and local visual evidence. Keep the orchestration progress record in ignored project work/ for the next session.

## Completion criteria

Report the implementation as complete only when its required interfaces and advertised workflow paths pass their gates. Strict-context execution is a core requirement; if it is unavailable, deliver an explicitly partial migration and name the missing runtime operation. Do not silently weaken that requirement. Offline implementation can be delivered while live tests are deferred, provided every route's live-verification status is explicit.

No publishing or new paid service is part of migration completion. Existing user-authorized uploads and unrelated agents' commits remain untouched. The migration must not reopen the stopped product experiment automatically.

## Final orchestrator report

List implemented families and supported operations; automation and context guarantees; regression/visual/audio evidence; unresolved or deferred live capabilities; exact integrated commits; clean/synchronized Git state; and a link to the next-agent handoff. Make it possible to run or refine one configured ad without reconstructing this development conversation.
