# Direct product video

Apply the chosen format as the main visual structure, then the chosen hook to the opening and the setting to the scene. `none` adds no hook; `auto` lets the product and format determine a suitable setting. Do not import other choices. A format's catalog beat count guides planning, but it does not prove that a provider can generate multiple shots in one request.

Inspect product references and facts, write a shot outline, then prepare an image prompt for a first frame with room for motion and later captions. Compare the frame against the real product before animating. Write a separate motion prompt that names the format's signature action, its visible start and end states, and the camera path through the requested duration. Check that the planned payoff would still identify the format with captions muted. A small plausible action must not replace a requested transformation, reveal or test. Compare any showcase with these beats; a picker preview is not a motion reference sent to the provider. If more than one clip is required, plan separate stages and their cost. Keep exact claims, logo and CTA for the local edit when generation cannot render them reliably.

Presenter formats may use a supplied presenter reference; a needed performer without one must be cast or reported as an unmet input, never borrowed from another project. No-presenter formats must not inherit selfie framing or spoken testimonials. The hook changes pacing or visual curiosity, not the product's verified properties. Record raw clips, edit plan, inspection and final artifact pointers as described in the shared execution guide.

Use `request.choices.avatar` and the frozen `request.presenterDescription` when the format needs a presenter. `none` lets you cast for that format; `custom` means match the supplied presenter reference. A named preset is a casting direction, not an existing image asset. Do not add a presenter to a format that does not need one. Incorporate `request.brief.direction` in the outline and both prompts where it fits the product facts.

For `execution.reviewMode: first-frame`, finish image generation and inspection, save `direct-state.json` with `status: first-frame-review`, and stop before video submission. The desk shows the frame and separate prompts. After the user approves, read `frame-approval.json`; its `frameSha256` must match the current `first-frame.bin`. Use its `videoPrompt` for video generation and resume the same frozen request. A revised image direction starts a new request ID, leaving this candidate intact. For `full`, inspect the first frame and continue automatically when accepted.

After inspecting the raw video, make a first pass at text overlays. Return caption text and output-frame windows in the inspection result; an empty list is valid when text would weaken the ad. The local edit plan saves that decision. The desk can later change those lines without regenerating footage.
