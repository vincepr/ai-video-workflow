# Local T3 connection

- Keep `credentials/t3.json` ignored and server-only. It contains `origin`, `cookie`, `threadId`, `expiresAt`, `runtimeMode` and `interactionMode`. Never print the cookie or pairing token.
- Read T3's `userdata/server-runtime.json` for its local origin. Pair through the installed CLI: `t3 auth pairing create --base-dir <T3 home> --label "Creator Desk" --ttl 5m --json`. Capture output privately, exchange its credential at `POST /api/auth/browser-session`, and retain the issued cookie and expiry.
- On Windows the bundled CLI can run with `ELECTRON_RUN_AS_NODE=1`, the T3 desktop executable and `resources/server.asar/apps/server/dist/bin.mjs` as the first argument. Do not extract signing keys or edit T3's database.
- Read `/api/orchestration/shell` with the client cookie. Match this workspace and the intended existing thread; preserve its modes. Do not select an unrelated or ambiguous thread.
- Sending uses a saved request ID and the server's configured destination. A receipt means T3 accepted a turn, not that rendering finished. Retry only on explicit request and retain the original command ID. Do not resend on reload.
